## 二、测试策略设计

### 2.1 总体原则（适合个人项目的轻量路线）

```
测试金字塔适配（个人项目版）：
         ╱╲
        ╱ E2E ╲           ← 少量：1-2 条核心用户旅程
       ╱────────╲
      ╱ 集成测试  ╲        ← 适量：插件 API + IPC 边界
     ╱────────────╲
    ╱ 单元测试      ╲      ← 主量：纯逻辑 + 核心模块
   ╱────────────────╲
```

- **不求全**：不追求覆盖率数字，优先覆盖核心逻辑和频繁改动的模块
- **够用即可**：测试运行时间控制在 5 秒内，不引入复杂 mock 框架
- **渐进引入**：先搭框架，再逐步补测试，不改现有代码为可测试性重构
- **工具链轻量**：vitest（与 Vite 同构） + 与现有 `tsconfig.json` 兼容

### 2.2 工具选型

| 层级 | 工具 | 理由 |
|------|------|------|
| 单元测试 | **vitest** | 与 Vite 同构、零配置、TypeScript 原生支持、watch 模式快 |
| 组件测试 | **vitest + @testing-library/react** | 轻量、贴近用户行为、避免重渲染细节断言 |
| E2E 测试 | **Playwright** | Electron 官方推荐、支持 `electron.launch()`、天然 async |
| Mock 策略 | **vi.mock** (vitest 内置) | 模块级 mock，无需额外依赖 |
| 覆盖率 | **c8** (vianode内置) | 零配置，`--coverage` 即用 |
| 代码检查 | **tsc --noEmit** | 已有，保持 |
| 提交前检查 | **simple-git-hooks** | 极轻，比 husky 少一层 shell |

### 2.3 安装命令

```bash

npm install -D vitest @testing-library/react @testing-library/jest-dom jsdom

# E2E 测试
```


### 4.2 event-bus 测试（`src/core/__tests__/event-bus.test.ts`）

```typescript
import { describe, it, expect, vi, beforeEach } from 'vitest';

// 需要 mock logger，因为 event-bus 在 handler 出错时调用 logger.error
vi.mock('../logger', () => ({
  error: vi.fn(),
  info: vi.fn(),
  warn: vi.fn(),
  debug: vi.fn(),
}));

// 类型测试中需要这个声明
import { bus } from '../event-bus';

describe('EventBus', () => {
  beforeEach(() => {
    // 清空所有监听器（通过内部调试接口）
    bus.debug(); // 用于验证
    // 由于没有公开的清空方法，每个测试用例独立测试时注意隔离
  });

  it('注册并触发事件', () => {
    const handler = vi.fn();
    bus.on('core:ready', handler);
    bus.emit('core:ready');
    expect(handler).toHaveBeenCalledTimes(1);
  });

  it('触发带参数事件', () => {
    const handler = vi.fn();
    bus.on('core:ready', handler);
    bus.emit('core:ready', { version: '0.1.0' });
    expect(handler).toHaveBeenCalledWith({ version: '0.1.0' });
  });

  it('once 只触发一次', () => {
    const handler = vi.fn();
    bus.once('core:ready', handler);
    bus.emit('core:ready');
    bus.emit('core:ready');
    expect(handler).toHaveBeenCalledTimes(1);
  });

  it('取消监听', () => {
    const handler = vi.fn();
    bus.on('core:ready', handler);
    bus.off('core:ready', handler);
    bus.emit('core:ready');
    expect(handler).not.toHaveBeenCalled();
  });

  it('handler 异常不传播', () => {
    const handler = vi.fn(() => { throw new Error('test error'); });
    const handler2 = vi.fn();
    bus.on('core:ready', handler);
    bus.on('core:ready', handler2);
    expect(() => bus.emit('core:ready')).not.toThrow();
    expect(handler2).toHaveBeenCalled();
  });

  it('debug 列出所有事件', () => {
    const handler = vi.fn();
    bus.on('core:ready', handler);
    bus.on('reminder:changed', handler);
    const list = bus.debug();
    expect(list).toContain('core:ready (1 listeners)');
    expect(list).toContain('reminder:changed (1 listeners)');
  });

  it('onDynamic 注册动态事件', () => {
    const handler = vi.fn();
    bus.onDynamic('custom:dynamic', handler);
    bus.emitDynamic('custom:dynamic', 'data');
    expect(handler).toHaveBeenCalledWith('data');
  });
});
```

### 4.3 command-registry 测试（`src/core/__tests__/command-registry.test.ts`）

```typescript
import { describe, it, expect, vi, beforeEach } from 'vitest';

vi.mock('../logger', () => ({
  info: vi.fn(),
  warn: vi.fn(),
  error: vi.fn(),
}));

import { registerCommand, listCommands, describeCommand, invokeCommand } from '../command-registry';
import type { CommandDefinition } from '../command-registry';

describe('CommandRegistry', () => {
  const testCmd: CommandDefinition = {
    command: 'test.hello',
    description: '测试命令',
    params: [{ name: 'name', type: 'string', required: true }],
    handler: (args) => `Hello, ${args.name}!`,
  };

  beforeEach(() => {
    // 每个测试开始前清理注册表（通过重新注册覆盖）
  });

  it('注册一条命令', async () => {
    registerCommand(testCmd);
    const result = await invokeCommand('test.hello', { name: 'World' });
    expect(result).toEqual({ ok: true, data: 'Hello, World!' });
  });

  it('返回未知命令错误', async () => {
    const result = await invokeCommand('unknown.cmd');
    expect(result).toEqual({
      ok: false,
      error: { code: 'not_found', message: '未知命令：unknown.cmd' },
    });
  });

  it('校验必填参数', async () => {
    registerCommand(testCmd);
    const result = await invokeCommand('test.hello', {});
    expect(result).toEqual({
      ok: false,
      error: { code: 'invalid_args', message: '缺少必填参数：name' },
    });
  });

  it('list 命令', () => {
    registerCommand(testCmd);
    const list = listCommands();
    expect(list).toContainEqual({ command: 'test.hello', description: '测试命令' });
  });

  it('describe 命令', () => {
    registerCommand(testCmd);
    const desc = describeCommand('test.hello');
    expect(desc).not.toBeNull();
    expect(desc!.params).toHaveLength(1);
  });

  it('拒绝非法命令 ID', () => {
    expect(() => registerCommand({
      command: 'invalid',
      description: 'test',
      handler: () => {},
    })).toThrow('非法命令 id');
  });
});
```

### 4.4 waiters 测试（`src/plugins/reminder/__tests__/waiters.test.ts`）

```typescript
import { describe, it, expect, vi, beforeEach } from 'vitest';
import { registerWaiter, fulfillWaiter, hasWaiter } from '../waiters';

describe('Reminder Waiters', () => {
  beforeEach(() => {
    vi.useFakeTimers();
  });

  it('注册并 fulfill', async () => {
    const onTimeout = vi.fn();
    const promise = registerWaiter('id1', 5000, onTimeout);
    fulfillWaiter('id1', { kind: 'responded', response: { actionId: 'ok', reason: '' } });
    const result = await promise;
    expect(result.kind).toBe('responded');
  });

  it('超时触发', async () => {
    const onTimeout = vi.fn();
    const promise = registerWaiter('id2', 5000, onTimeout);
    vi.advanceTimersByTime(5000);
    const result = await promise;
    expect(result.kind).toBe('timeout');
  });

  it('supersede 旧 waiter', async () => {
    const onTimeout1 = vi.fn();
    const onTimeout2 = vi.fn();
    const p1 = registerWaiter('id3', 5000, onTimeout1);
    const p2 = registerWaiter('id3', 5000, onTimeout2);
    expect(await p1).toEqual({ kind: 'superseded' });
    fulfillWaiter('id3', { kind: 'dismissed' });
    expect(await p2).toEqual({ kind: 'dismissed' });
  });

  it('hasWaiter 检测', () => {
    registerWaiter('id4', 5000, vi.fn());
    expect(hasWaiter('id4')).toBe(true);
    fulfillWaiter('id4', { kind: 'dismissed' });
    expect(hasWaiter('id4')).toBe(false);
  });
});
```

## 七、端到端测试方案（Electron）

### 7.1 架构

```
Playwright 测试脚本
    │
    ├── electron.launch() ──→ Electron 主进程
    │        │
    │        └── 加载应用（dev 模式或构建后）
    │
    ├── page.evaluate() ──→ 渲染进程操作
    │
    └── ipc: 通过 window.assistant 验证状态
```

### 7.2 关键测试场景

| 场景 | 步骤 | 验证点 |
|------|------|--------|
| 应用启动 | 启动 Electron | 悬浮球窗口出现、IPC 通道就绪 |
| 计算器 | 点击计算器标签 → 输入表达式 → 计算结果 | 结果显示正确、历史记录更新 |
| 提醒创建 | 创建提醒 → 检查列表 | 提醒出现在列表中、状态为 active |
| 知识库笔记 | 新建笔记 → 编辑 → 搜索 | 笔记保存成功、搜索命中 |
| 面板切换 | 点击悬浮球 → 展开面板 → 切换标签 | 各标签页渲染正常 |

## 九、风险与注意事项

1. **sql.js 双进程问题**：项目采用"整库内存快照 + 整库覆盖落盘"模型，集成测试中若同时操作同一数据库文件，存在静默写丢失风险。测试应使用独立内存数据库，不操作真实 `.data/assistant.db`。

2. **Electron 依赖**：`src/core/logger.ts` 直接依赖 `electron` 的 `app.getPath()`，但 `src/core/db.ts` 采用了 `process.cwd()` 作为 fallback。测试时需 mock electron 模块。

3. **插件铁律**：项目规定"插件之间禁止直接 import"，测试属于特殊场景——测试文件直接 import 被测试的 `api.ts` 是合理的，因为测试不参与生产运行。

4. **随机性测试**：`dev-utils` 的 UUID 生成包含 `Math.random()`，测试时需要使用 `vi.spyOn(Math, 'random')` 进行 mock，或者测试格式而非具体值。

5. **CLI 测试**：`src/cli/index.ts` 依赖 CLI 框架，建议在集成测试层级测试，而非单元测试。
