## 二、详细发现

### 🔴 1. `agent.update` 省略 title 时把标题覆写为 `"undefined"`
`safeInput.title = String(input.title)` 无兜底，UPDATE 分支（~502 行）直接用其做绑定参数；INSERT 分支（529 行）却用 `input.title || ''`。
- **触发**：Agent 只更新 `body`/`stage` 省略 `title` → `String(undefined)="undefined"` → 标题列被污染，面板显示 "undefined"。
- **修复**：UPDATE 分支仅在 `input.title !== undefined` 时更新 title，或与 INSERT 一致加兜底。

### 🔴 2. `reminder.list()` 默认 status 丢失，返回全部状态
旧代码对缺失/非法 status 回退 `'active'`；新代码用 `hasStatus` 守卫，不传 status 时省略 `WHERE`，返回 active+done+dismissed 全部。CLI 文档（`index.ts:193-206`）仍写「默认 active」。
- **触发**：`uuutil call reminder.list`、ReminderCenter 初始加载、旧 Agent workflow 意外拿到已归档提醒（可能含敏感历史）。
- **修复**：恢复默认 `'active'`；如需「全部」语义则同步更新 CLI 文档并显式支持 `status:'all'`。

### 🔴 3. 插件「禁用」后能力仍存活
`deactivate()` 只停轮询，不反注册 `activate()` 注册的 6 条 `clipboard.*` CLI 命令与 bus 监听；`setPluginEnabled(false)`（317-333 行）也只调 `deactivate()` + `loadedPlugins.delete`，无强制清理。**根因：`command-registry` 没有反注册 API**。`hello-world` 的 `deactivate` 同为空操作。
- **触发**：`plugin.disable clipboard` 后，外部仍能 `uuutil call clipboard.list` 读写数据库。
- **修复**：给 command-registry 增加 `unregisterByScope(pluginId)`；`setPluginEnabled(false)` 时强制清理该插件命令与 bus 监听（可按 pluginId 前缀批量 `bus.off`）。

### 🔴 4. 知识库筛选 + 搜索无法叠加，且存在竞态
`loadData()` 三元链 `filter ? getNotes(filter) : search ? searchNotes() : getNotes()`——filter 与 search **互斥**，同时非空时 search 被静默丢弃。搜索（300ms 防抖，279 行）与筛选（立即，298 行）两个独立 useEffect 各自取数，全文件无 AbortController/序列号。额外 bug：清空搜索词但 filter 激活时（281-282 行）调无参 `loadData()` 丢掉筛选结果。
- **触发**：分类筛选下输入关键词，看到的是全库搜索而非「该分类下匹配项」；快速操作时结果抖动。
- **修复**：筛选与搜索合并到单一 state + 单一防抖 effect；`loadData` 支持 filter 与 keyword 组合查询；用序列号丢弃过期响应。

### 🟠 5. `core:ready` 回调无异常隔离
`bus.on('core:ready', () => { ensureClipboardTable(); startMonitor(); })` 无 try/catch。建表抛异常 → `startMonitor()` 不执行，EventBus 静默吞异常（仅一条 logError）。此时 `activate()` 已返回、插件已标记激活、CLI 命令已注册。
- **触发**：DB 损坏/权限问题时，`clipboard.list` 报 `no such table`，根因深埋日志难以定位。
- **修复**：回调内 try/catch 隔离两次调用，建表失败用 `logError('clipboard', ...)` 明确记录根因。

### 🟠 6. LIKE 通配符未转义
`params.push(`%${keyword}%`)` 直接拼接，未转义关键词内的 `%`/`_`，也无 `ESCAPE` 子句。
- **触发**：搜 `50%` 命中 `501`/`50x`；搜 `a_b` 命中 `axb`/`a3b`（非注入，参数已绑定，但结果错误）。
- **修复**：`keyword.replace(/[%_\\]/g, '\\$&')` + SQL 加 `ESCAPE '\'`。

### 🟡 7. `isExamplePluginBlocked()` fail-open
catch 返回 `false`（=放行），但该函数默认立场是「拦截示例插件」，异常时应 fail-closed 返回 `true`。注释承认「为与 isPluginDisabled 一致」，但两者默认语义相反。
- **触发**：DB 异常时示例插件被加载进生产（概率低，但防御方向错误）。
- **修复**：catch 返回 `true`。

### 🟡 8. 示例插件迁移无条件覆盖
迁移 SQL `UPDATE _plugins SET enabled=0 WHERE id=?` 不判断当前值，幂等性完全依赖 `_meta` 标记 key 不被删除。
- **触发**：`_meta` 标记被删（手动/损坏修复）→ 迁移重跑强行禁用用户已 `plugin.enable` 的示例插件。
- **修复**：`UPDATE ... SET enabled=0 WHERE id=? AND enabled != 0`。

### 🟠 9. 8 处 `console.*` 绕过 `core/logger`
违反 CONVENTIONS.md 铁律 §4 与 CLAUDE.md §6（主进程/核心模块必须用 `core/logger`）。位置：`clipboard/index.ts:36,40,137,150,154,161,167` + `clipboard.ipc.ts:28`。`core/logger` 已导出 `info/warn/error(scope, message, meta?)`。plugin-loader 新代码已正确用 logInfo/logError，形成不一致。
- **修复**：改用 `info('clipboard', ...)` / `error('clipboard', ...)`。

### ⚪ 10. `recordEvent()` 每次调用 `COUNT(*)` 全表扫描
每次 INSERT 后无条件 `SELECT COUNT(*) FROM _events_log`（无 WHERE 全表扫描），仅为判断是否超 5500 行阈值，无频率控制。表达数千行后，calculator/dev-utils/hello-world 每次操作都付一次全表扫描。
- **修复**：自维护计数器，或每 N 次 INSERT 才 COUNT 一次。

### ⚪ (附) `enforceLimit()` 每次 INSERT 触发
`record()` 每次新增后无条件调 `enforceLimit()`，执行含 `ORDER BY last_used_at DESC LIMIT 200` 的全表排序子查询，即使表远未达上限。
- **修复**：先 `SELECT COUNT(*) WHERE pinned=0` 预检，仅 ≥ MAX_ITEMS 时才裁剪。

## 三、架构层面观察（非 bug，供后续参考）

- **示例插件概念硬编码在 core**：`EXAMPLE_PLUGIN_IDS` Set + 4 个专用函数。建议改为 `PluginManifest.defaultEnabled?: boolean`，由插件自声明，core 不维护 ID 名单。
- **IPC 存在两条并行路径**：clipboard/reminder 直接 `import api.ts`（同步），calculator/knowledge-base 走 bus 桥接（`waitForPluginEvent` 异步配对）。建议统一为单一路径。
- **`bindBus` 广播样板重复**：clipboard.ipc.ts / reminder.ipc.ts 各复制一份「守卫 + 遍历窗口广播」。建议抽取 `createBusBroadcast(eventName, ipcChannel, transform?)`。
- **插件 schema 管理分散**：各插件在 `core:ready` 自行 `CREATE TABLE`，无版本化迁移。建议 core 暴露 `registerPluginSchema(pluginId, {version, migrations})`。
- **代码复用**：`selectRows`（3 个插件 API 各一份）、`formatRelativeTime`（3 份副本）、文本截断逻辑（多份）建议抽取到 `core/db` 与 `renderer/utils/`。
