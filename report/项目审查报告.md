## 🚀 建议改进的地方

### 🔴 高优先级

#### 1. IPC 处理严重重复

**问题：** 主进程有大约 200 行代码都是同一个模式，每个插件的每个方法都要手写一遍 IPC：

```typescript
ipcMain.handle('plugin:xxx:yyy', (...) => {
  return new Promise(resolve => {
    bus.on('xxx:result', handler);
    bus.emit('xxx:invoke', ...);
  });
});
```

**解决方案：** 做一个通用的插件 IPC 注册器，10 行代码代替 200 行：

```typescript
// 自动注册插件 IPC
function registerPluginIpc(pluginId: string, methods: string[]) {
  for (const method of methods) {
    ipcMain.handle(`plugin:${pluginId}:${method}`, (_event, ...args) => {
      return new Promise(resolve => {
        bus.on(`${pluginId}:result:${method}`, function handler(data) {
          bus.off(`${pluginId}:result:${method}`, handler);
          resolve(data.result);
        });
        bus.emit(`${pluginId}:${method}`, ...args);
      });
    });
  }
}
```

---

#### 2. 事件总线缺少类型安全

**问题：**

```typescript
export type EventHandler = (...args: any[]) => void;
```

事件名和参数都是 `any`，写错了编译器也不报错。

**解决方案：** 加一层类型映射：

```typescript
interface EventMap {
  'core:plugins-loaded': [Plugin[]];
  'calculator:calculate': [string];
  'calculator:result': [{ expression: string; result: string }];
  // ... 所有事件在这里定义
}

class EventBus {
  on<K extends keyof EventMap>(event: K, handler: (...args: EventMap[K]) => void): void;
  emit<K extends keyof EventMap>(event: K, ...args: EventMap[K]): void;
}
```

### 🟡 中优先级

#### 3. 数据库优化

- **防抖保存：** 现在 `autoSave()` 每次操作都写磁盘，建议加 500ms 防抖
- **错误处理：** `db.run()` 缺少 try-catch，SQL 出错了插件不知道
- **事务支持：** 批量操作可以加事务提升性能

#### 4. 插件 API 暴露标准化

现在插件暴露能力靠约定的事件名，没有统一的 `exportApi()` 机制。可以参考 VS Code 的 `vscode.commands.registerCommand` 设计一个标准的 API 注册方式。

#### 5. 依赖版本回退到稳定版

```json
// 建议从 RC 版换回稳定版
"react-router-dom": "^6.x",  // v7 还没正式发布
"vite": "^5.x",              // v6 还在 RC
```

---

### 🟢 低优先级（锦上添花）

#### 6. 增加最简插件模板

现在的 4 个插件同时也是示例，可以抽一个 `plugins/examples/minimal-plugin` 作为最简模板，方便新插件开发。

#### 7. 插件热重载

开发时监听插件目录变化，自动 reload 插件，提升开发体验。

#### 8. 核心层单元测试

event-bus、db、plugin-loader 这几个核心模块很适合写单元测试，保证框架稳定性。

---

## 🎯 总结

**这是一个起点非常高的项目！** 架构设计远超一般的个人项目级别。现在的代码已经可以作为一个很好的插件化应用框架来用了。

核心问题就是 IPC 代码重复和事件总线类型安全，这两个改完，代码质量还能再上一个台阶。

**下一步建议：**
1. 先解决 IPC 重复问题（1 小时工作量）
2. 给 EventBus 加上类型安全（2 小时工作量）
3. 其他优化可以慢慢做
