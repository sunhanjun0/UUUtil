# UUUtil 应用功能整理及后续开发必要性研究

## 一、项目概述

UUUtil 是一个**插件化个人辅助桌面工具**，基于 Electron + React + TypeScript 构建，使用 sql.js/SQLite 做本地持久化。核心设计思想是：内核只提供基础设施（窗口、事件总线、插件加载、数据库），具体功能由独立插件实现，沉淀日常高频小工具。

### 2.2 已实现插件 ✅ 全部完成

#### 1. **calculator** - 计算器
- 功能：鼠标+键盘输入、连续计算、保留最多 10 条历史记录
- 状态：✅ 功能完整

#### 2. **dev-utils** - 开发工具
- 功能：JSON 格式化/校验、SQL 格式化、Base64 编解码、时间戳转换、正则测试、UUID 生成
- 状态：✅ 功能完整

#### 3. **focus** - 焦点看板
- 功能：注意力观察系统（非 TODO 工具），FIE 外部接入、焦点对象泡泡图、权重衰减、健康度计算、标签系统
- 设计：数据由外部系统上报，应用只读展示
- 状态：✅ 功能完整，生产可用

#### 4. **knowledge-base** - 知识库
- 功能：笔记增删改查、分类、标签、全文搜索
- 状态：✅ 功能完整

#### 5. **reminder** - 提醒框架
- 功能：
  - `reminder.notify`：单向推送提醒
  - `reminder.ask`：阻塞式等待用户确认
  - `reminder.respond`：手动响应
  - `agent.update`/`agent.wait`/`agent.query`/`agent.close`：Agent 专属模式，同 topic 自动合并版本历史
- UI：提醒中心页支持筛选（全部/active/Agent）、已完成归档
- 状态：✅ 功能完整，最近 bug 已修复（SQL bind 错误处理）

#### 6. **terminal** - 集成终端
- 功能：
  - 多标签页、重命名标签
  - 基于 node-pty 的原生 PTY
  - 支持 tmux 会话持久化恢复（应用重启后 tmux 会话仍然保留）
  - 自适应面板 resize
  - xterm.js 前端渲染
- 状态：✅ 功能完整，最近修复 Orca tmux 嵌套冲突

## 三、代码质量与架构评估

### 3.1 符合架构设计规则

根据 `docs/CONVENTIONS.md`：

1. ✅ **插件隔离**：插件之间无直接 `import`，全部通过 EventBus 通信
2. ✅ **插件 API**：每个插件对外接口统一放在 `api.ts`
3. ✅ **数据库统一入口**：所有操作通过 `core/db`，写后调用 `autoSave()`
4. ✅ **事件命名空间**：`core:*` 内核、`plugin-id:*` 插件，规则执行到位
5. ✅ **错误处理**：EventBus 捕获异常，核心日志统一记录
6. ✅ **日志约束**：不记录敏感信息，统一使用核心日志框架

### 3.2 技术债务评估

| 类别 | 情况 | 严重度 |
|------|------|--------|
| 未完成功能 | 几乎没有，翻译/终端都已实现 | - |
| 已知 open bug | 最近修复了 `reminder` agent.update SQL bind 和 `terminal` tmux 嵌套冲突，目前无已知严重 bug | 无 |
| 代码重复 | 内核代码清晰，插件间独立无共享实现，重复度低 | 低 |
| 类型覆盖 | TypeScript 全项目覆盖，`sql.js` 等少数补充了类型声明 | 好 |
| 测试覆盖率 | 暂无自动化测试，属于个人工具项目，可接受 | - |

## 五、结论与建议

### 5.1 当前状态结论

**项目已达到「可用的个人日常辅助工具」状态**：

- 内核架构稳定，插件机制工作良好
- 核心功能都已实现且可正常使用
- 最近开发的 `reminder` 和 `terminal` 都已完成并修复了已知 bug
- 没有大块未完成的核心功能

### 5.2 推荐后续开发顺序（按必要性）

1. **P1 高必要性**：
   - **剪贴板历史插件** —— 高频需求，投入产出比很高

2. **P2 中高必要性**：
   - **定时提醒能力** —— 补全提醒框架的核心场景
   - **知识库问答 RAG** —— 利用现有知识库和 AI 框架产生新价值
   - **批量文件处理插件** —— 符合"日常小工具"定位
   - **Windows/Linux 打包测试** —— 如果需要分享给其他平台用户

3. **P3 中低必要性**（有空再做）：
   - 深色模式主题切换
   - 白板元素对齐辅助线
   - AI 助手会话分类
   - 网络请求调试插件

4. **P4 低必要性**（不推荐做）：
   - 自动化测试（个人工具项目不需要）
   - 插件市场（个人使用不需要）
   - 密码管理（重复造轮子）

### 5.3 必要性总结

项目当前已经**满足了最初的设计目标**（插件化沉淀个人日常小工具），核心功能完整。后续开发属于**增量扩展**，而非补全核心缺口。建议按 P1 → P2 顺序选择性开发，优先做投入产出比高的高频功能。
